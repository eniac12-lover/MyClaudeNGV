# ISO 26262 Part 6 — 소프트웨어 통합시험 방법

> 공개적으로 통용되는 ISO 26262 Part 6의 소프트웨어 통합시험 방법 표를 요약한 것입니다. ASIL별 권고 강도(++/+/o 등)는 표준 원문 및 프로젝트 Safety Plan과 대조하세요.

## 통합시험 방법(Method)

| 방법 | 설명 | 이 프로젝트에서의 적용 |
|---|---|---|
| 요구사항 기반 시험 (Requirements-based Test) | 통합된 컴포넌트 조합이 배분된 요구사항(SR/SWR)을 충족하는지 검증 | `requirements-analyst`/`architecture-design` 산출물의 요구사항을 근거로 케이스 도출 |
| 인터페이스 시험 (Interface Test) | 컴포넌트 간 인터페이스가 명세(오퍼레이션, 데이터 타입, 사전/사후조건)대로 동작하는지 검증 | `architecture-design`의 `references/interface-design.md` 인터페이스 명세 표 기준 |
| 결함 주입 시험 (Fault Injection Test) | 의도적으로 오류/결함 조건을 주입해 오류 감지·처리·안전 상태 전이가 올바른지 검증 | 안전 관련(ASIL) 인터페이스의 사전조건 위반, 통신 두절, 잘못된 값 주입 등 |
| 자원사용 시험 (Resource Usage Test) | 통합 후 실제 자원(CPU/메모리/스택/통신 대역폭) 사용이 설계 추정치 내에 있는지 검증 | `architecture-design` 기본 양식 §8(자원 추정)과 실측값 비교 |
| 백투백 비교 시험 (Back-to-back Comparison Test) | 모델(있는 경우)과 실제 코드의 동작을 동일 입력에 대해 비교 | 모델 기반 설계 산출물이 있는 컴포넌트에만 적용, 없으면 해당 없음으로 명시 |

## 케이스 도출 기법과의 관계

위 "방법"은 **무엇을 검증할 것인가**(시험 목적)를 정의하고, `tdd`의 `references/test-design-techniques.md`(동등분할/경계값/결정테이블/상태전이/오류추측 등)는 **어떤 입력을 고를 것인가**(케이스 도출 방식)를 정의합니다. 하나의 테스트 케이스는 보통 이 두 축을 조합해 기술합니다.

예) `Technique` 컬럼 기입 예시: `"인터페이스 시험 + 경계값분석"`, `"결함 주입 시험 + 오류추측"`, `"요구사항 기반 시험 + 결정테이블"`.

## 적용 우선순위

- 안전 관련(ASIL) 인터페이스: 인터페이스 시험 + 결함 주입 시험을 우선 적용.
- 성능/자원 제약이 있는 NFR과 연계된 컴포넌트: 자원사용 시험을 추가.
- 모델 기반 설계 산출물이 없는 대다수 컴포넌트: 요구사항 기반 시험 + 인터페이스 시험을 기본으로 적용.
