# 컴포넌트 통합 순서 정의 절차

목적: 아키텍처의 인터페이스 의존 관계를 근거로, 실현 가능하고 리스크를 낮추는 컴포넌트 통합 순서를 도출합니다. 이 결과는 이후 SYS.4/SWE.5(통합 및 통합 테스트) 전략의 입력이 됩니다.

## 절차

1. **의존성 그래프 작성**: `references/interface-design.md`의 인터페이스 명세 표에서 "사용 컴포넌트 → 제공 컴포넌트" 방향의 의존 관계를 모두 추출해 방향 그래프를 만듭니다.
2. **순환 의존 확인**: 그래프에 순환이 있으면 §3(응집도/결합도)에서 이미 순환 의존이 없어야 한다고 규정했으므로, 발견 시 설계를 수정하거나(권장) 불가피하면 순환을 끊을 통합 지점(예: 스텁 사용)을 명시합니다.
3. **위상 정렬(topological sort)**: 의존 대상(제공자) 컴포넌트를 먼저, 의존하는(사용자) 컴포넌트를 나중에 통합하는 순서를 기본으로 도출합니다.
4. **리스크 기반 조정**: 아래 기준으로 순서를 조정할 수 있습니다(조정 시 근거를 기록).
   - 안전 관련(ASIL 높은) 컴포넌트와 그 안전 메커니즘은 가능한 한 이른 단계에 통합해 충분한 검증 시간을 확보
   - 기술적 리스크가 높거나 신규 기술을 사용하는 컴포넌트는 조기 통합해 문제를 일찍 발견
   - 외부 공급자/타 팀 의존 컴포넌트는 가용 일정에 맞춰 배치
5. **스텁/드라이버 식별**: 아직 통합되지 않은 하위 의존 컴포넌트가 필요한 경우, 해당 단계에서 사용할 스텁(stub, 피호출자 대체) 또는 드라이버(driver, 호출자 대체)를 명시합니다.
6. **결과 문서화**: 아래 표 형식으로 통합 순서를 기록합니다.

| 순서 | 통합 대상 컴포넌트 | 선행 통합 필요 컴포넌트 | 필요한 스텁/드라이버 | 이 순서를 선택한 이유 |
|---|---|---|---|---|
| 1 | SensorComponent | 없음 | ControlComponent 드라이버(테스트용 호출자) | 최하위 의존 요소, 리스크 있는 신규 하드웨어 드라이버 조기 검증 |
| 2 | ActuatorComponent | 없음 | ControlComponent 드라이버 | 안전 관련 출력 경로 조기 검증 |
| 3 | ControlComponent | SensorComponent, ActuatorComponent | 없음 | 두 하위 인터페이스가 모두 준비된 후 통합 |

## 검토 체크리스트

- [ ] 모든 컴포넌트가 통합 순서표에 포함되어 있는가?
- [ ] 각 단계의 "선행 통합 필요 컴포넌트"가 실제 인터페이스 의존과 일치하는가?
- [ ] 안전 관련 컴포넌트의 통합 시점과 근거가 명시되어 있는가?
- [ ] 순환 의존으로 인한 스텁 사용이 있다면 그 사유가 명확한가?
