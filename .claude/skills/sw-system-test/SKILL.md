# SW 시스템 테스트 케이스 생성 (SWE.6)

SW 요구사항 명세서 기반으로 SW 시스템(검증/Qualification) 테스트 케이스를 생성하기 위한 방법론 스킬입니다. 이 스킬은 "무엇을 근거로, 어떤 기법으로, 어떤 원칙으로" 테스트 케이스를 설계할지에 대한 방법론만 정의합니다. 요구사항 분석, 사용자와의 확인, 실제 산출물(xlsx) 작성은 이 스킬을 사용하는 에이전트(`sw-system-tester`)가 수행합니다.

## 범위 — SWE.5(통합시험)와의 경계

이 스킬은 **블랙박스, 요구사항 기반** 시스템 시험입니다 — SW 요구사항 명세서에 적힌 대로 동작하는지만 검증하고, 아키텍처 내부 구조나 인터페이스 구현 방식은 알 필요가 없습니다. 컴포넌트 간 인터페이스·통합 순서에 근거한 화이트박스성 시험은 `integration-test`(SWE.5) 스킬의 범위입니다 — 이 스킬에서 아키텍처 문서를 테스트 베이시스로 쓰지 않습니다. 함수 단위 화이트박스 시험(SWE.4)은 `tdd` 스킬(단위 테스트)이 구현과 함께 수행합니다.

## 기반지식

- **ISO 26262 Part 6**: 소프트웨어 시스템(검증) 테스트에 대한 요건. 특히 ASIL 등급이 할당된 요구사항은 판정기준의 전 분기(경계값, 조건 조합)를 빠짐없이 검증해야 합니다.
- **A-SPICE SWE.6**: 소프트웨어 검증시험(Qualification Test)에 대한 Base Practice. 양방향 추적성(요구사항 ↔ 테스트 케이스)과 표준화된 시험 절차를 요구합니다.
- **ISO 29119 및 ISTQB**: 테스트 시나리오·테스트 케이스 설계 프로세스와 용어 체계(긍정/부정 분류 등)의 근거로 사용합니다.
- **ISO 25010 (SQuaRE)**: 비기능(품질) 요구사항을 분류하는 기준입니다.

## 적용 대상 테스트 기법

요구사항의 성격에 맞춰 기법을 선택하고, 각 테스트 케이스의 `Technique` 항목에 실제로 적용한 기법을 명시합니다. **기법 목록과 설명은 별도로 정의하지 않고 `tdd`의 `references/test-design-techniques.md`를 그대로 사용합니다**(전수조합/페어와이즈용 오픈소스 도구 PICT 사용법 포함, 이 프로젝트의 유일한 테스트 설계 기법 카탈로그). 긍정(Positive)/부정(Negative) 케이스 구분도 같은 파일의 정의를 따릅니다.

## 비기능 요구사항 분류 기준

비기능 테스트 케이스를 ISO 25010 품질 특성별로 그룹화할 때는 `requirements-analyst`의 `references/nfr-iso25010.md`의 특성/하위특성 표를 그대로 사용합니다(별도로 다시 정의하지 않습니다). 각 NFR이 이미 요구사항 명세서 작성 시 그 표의 어떤 특성에 매핑되어 있는지(`requirements-analyst` 산출물)를 그대로 이어받아 테스트 케이스를 분류합니다 — 시스템 테스트 단계에서 임의로 다른 특성으로 재분류하지 않습니다.

## 작성 원칙

- 의미 없이 테스트 커버리지 수치 달성만을 목적으로 하는 케이스는 생성하지 않습니다.
- 테스트의 예상 결과를 임의로 가정하지 않습니다. 명세서에 근거가 없다면 이 스킬을 사용하는 에이전트가 사용자에게 확인을 받아야 합니다.
- 프로젝트에서 정한 테스트 커버리지 목표(예: `CLAUDE.md`에 명시된 기준)를 준수합니다.
- 실행자가 그대로 재현할 수 있는, 실행 가능한 테스트 케이스만 작성합니다.
- 기법 선택이나 커버리지 범위 설정이 판단하기 어려운 경우 임의로 결정하지 말고, 이 스킬을 사용하는 에이전트를 통해 사용자 검토를 받습니다.
- 명세서에 직접적 근거는 없으나 QA 관점에서 추가를 제안하고 싶은 테스트 케이스는 테스트 케이스명 끝에 "(제안)"이라고 표시해 구분합니다.
- 요구사항 명세서 원문에 없거나 원문보다 엄격한 판정기준을 사용자 확인을 거쳐 확정한 경우, "확정 근거" 열에 확정 일자와 승인 주체를 기록합니다(`references/system-test-template.md` 표에 없는 프로젝트 고유 컬럼이므로, 사본에 열을 추가해 사용).

## 추적성

`requirements-analyst`의 `references/traceability.md` §0에 정의된 공식 매트릭스(`TPL-TRC-001_...xlsx`)에서 해당 요구사항 행을 찾아 `SWE.6` 컬럼에 이 시스템 테스트 케이스 ID를 채웁니다. 새 매트릭스나 별도 추적 방식을 만들지 않습니다.

## 산출물 구조

`references/system-test-template.md`의 컬럼 구조를 따르며:

- 비기능 요구사항에 대한 테스트 케이스: 별도의 "비기능 테스트 케이스" 시트, ISO 25010 품질 특성별로 구분(위 §비기능 요구사항 분류 기준)
- 요구사항 원문에 없거나 원문보다 엄격하게 사용자 확인을 거쳐 확정한 판정기준: "확정 근거" 열에 확정 일자와 승인 주체 기록
