# 함수 계약 / 알고리즘 / 결정표 작성 가이드

## 함수 계약(문서 §5) 필수 항목

`architecture-design`의 `references/interface-design.md` 인터페이스 명세 원칙을 컴포넌트 간 경계뿐 아니라 **컴포넌트 내부의 핵심 함수**에도 동일하게 적용합니다.

| 항목 | 설명 |
|---|---|
| 시그니처 | 함수명, 파라미터(이름/타입), 반환 타입 |
| 사전조건(precondition) | 호출 전 성립해야 하는 조건(널 체크, 범위, 상태 등) |
| 사후조건(postcondition) | 호출 후 보장되는 결과/상태 |
| 부작용(side effect) | 전역/공유 상태 변경, I/O, 로깅 등 |
| 예외/오류 | 발생 가능한 예외/오류 코드와 호출자의 처리 방법 |
| 시간 제약(해당 시) | 최대 실행시간, 호출 주기 |
| 재진입/동시성(해당 시) | 스레드 안전성, 재진입 가능 여부 |

## 핵심 알고리즘(문서 §6) 서술 규칙

- 의사코드 또는 흐름도(Mermaid `flowchart`)로 처리 순서를 표현합니다.
- 모든 분기 조건을 명시적으로 기술합니다 — "적절히 처리한다", "필요시 재시도한다" 같은 모호한 표현 금지(`requirements-analyst`의 `references/requirement-writing-rules.md` 명확성 규칙과 동일 기준).
- 경계값(최소/최대/0/음수/빈 입력 등)에서의 동작을 명시적으로 다룹니다.
- 계산식이 있으면 근거(출처 요구사항 ID 또는 도메인 규칙)를 함께 기록합니다.

## 정책 의사결정표(문서 §7) 형식

| 조건 1 | 조건 2 | ... | 우선순위 | 기대 동작 | 충돌 시 해결 규칙 |
|---|---|---|---|---|---|
| 예 | 아니오 | | 1 | 동작 A 수행 | - |
| 예 | 예 | | 2 | 동작 B 수행 (조건2 우선) | 조건1·2 동시 성립 시 조건2 우선 |

- 조건 조합을 모두 나열해 **빠짐(gap)**이 없는지 확인합니다(다루지 않은 조합이 남아 있으면 명시적으로 "정의되지 않음/발생 불가"로 표시).
- 서로 다른 두 행이 같은 조건 조합에 대해 다른 동작을 요구하지 않는지(모순) 확인합니다 — 발견되면 우선순위 규칙으로 명확히 해소합니다.

## 상태전이 상세(문서 §8) 서술 항목

`architecture-design`의 상위 State Machine 다이어그램을 아래 수준까지 구체화합니다.
- 상태를 저장하는 변수/구조체 위치
- 각 전이를 유발하는 이벤트와 가드(guard) 조건
- 전이 시 수행되는 함수(entry/exit/transition action)
- 타이머 기반 전이(해당 시) 및 타임아웃 값
- 초기화 시 시작 상태와 초기화 함수
