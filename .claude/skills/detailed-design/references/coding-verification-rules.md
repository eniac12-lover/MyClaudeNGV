# 코딩 및 검증 규칙 정의 가이드 (문서 §11)

이 절에서는 "무엇을, 어떤 기준으로 검증할 것인가"를 정의합니다. 실제 테스트 작성/실행은 SWE.4(단위검증) 범위입니다.

## 코딩 표준

- 사용 언어의 표준 스타일 가이드(예: Python이면 PEP 8) 또는 조직 코딩 표준을 명시합니다.
- 안전 관련(ASIL) 단위는 해당 언어/도메인의 안전 코딩 표준(예: C/C++이면 MISRA C 계열) 준수 여부와 예외 처리 방침을 명시합니다. 정확한 표준 조항은 표준 원문/조직 규정과 대조하세요.
- 금지/제한 패턴(예: 동적 메모리 할당 제한, 재귀 제한, goto 금지 등)이 있다면 이 절에 명시합니다.

## 정적분석

- 사용할 정적분석 도구와 규칙셋을 명시합니다.
- 통과 기준(예: High/Critical 이슈 0건)을 정량적으로 정의합니다.

## 단위검증 기준 (SWE.4로 실행)

- 커버리지 목표(구문/분기/MC-DC 등, ASIL에 따라 요구 수준이 다를 수 있음 — 프로젝트 Safety Plan 확인)를 정의합니다.
- 각 함수 계약(§5)의 사전/사후조건이 테스트 케이스로 어떻게 검증될지 원칙만 정의합니다(구체적 테스트 케이스 작성은 SWE.4 스킬 범위).

## 리뷰 기준

- 상세설계/코드 리뷰 체크리스트 항목(예: 함수 계약 준수, 명명 규칙, 복잡도 임계값)을 정의합니다.
- 리뷰 기록 방식은 `aspice-auditor` 스킬의 PA2.2(작업산출물 관리) 관점과 일치해야 합니다 — 리뷰가 형식적으로 끝나지 않고 실제 발견사항 반영까지 추적되도록 기록 위치를 명시합니다.

## SWE.4(단위검증) 스킬과의 관계

이 프로젝트에 아직 SWE.4 전용 스킬이 없다면, 여기서 정의한 기준이 향후 그 스킬의 입력이 됩니다. 이 절에서 검증 기준을 실행 불가능하게(측정 불가능하게) 정의하지 마세요 — `requirements-analyst`의 `references/nfr-iso25010.md`에 있는 "실행 가능한 검증 방안" 3요소(도구/절차 + 조건 + 정량적 합격기준) 원칙을 그대로 적용합니다.
