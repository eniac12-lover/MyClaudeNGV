# 비기능 요구사항(NFR) — ISO/IEC 25010 기준 작성 가이드

> 아래 특성/하위특성 목록은 ISO/IEC 25010(SQuaRE 제품 품질 모델)의 공개적으로 통용되는 8대 특성을 요약한 것입니다. 프로젝트가 참조하는 정확한 판(edition, 예: 2011 vs 2023 개정판 — 2023년 개정판은 "Safety" 특성이 추가된 것으로 알려져 있음)에 따라 세부 하위특성 명칭/구성이 다를 수 있으므로, 공식 표준 원문과 대조해 확정하세요.

## 품질 특성 / 하위특성

| 특성 | 하위특성(예) | 전형적 NFR 예시 영역 |
|---|---|---|
| 기능 적합성 (Functional Suitability) | 완전성, 정확성, 적절성 | 기능이 명세된 요구를 정확히 수행하는지(주로 FR과 겹치므로 NFR에서는 보조적으로만 사용) |
| 성능 효율성 (Performance Efficiency) | 시간 반응성, 자원 사용성, 용량 | 응답시간, 처리량(throughput), CPU/메모리 사용률, 최대 동시 사용자 수 |
| 호환성 (Compatibility) | 공존성, 상호운용성 | 다른 시스템/버전과의 동시 운용, 데이터 교환 표준 준수 |
| 사용성 (Usability) | 인지적 적절성, 학습성, 운용성, 오류 방지, UI 심미성, 접근성 | 조작 완료까지 필요한 클릭/단계 수, 오조작률, 접근성 표준 준수 |
| 신뢰성 (Reliability) | 성숙성, 가용성, 결함 허용성, 회복성 | MTBF, 가용률(%), 고장 시 복구시간(MTTR), 결함 주입 시 동작 |
| 보안성 (Security) | 기밀성, 무결성, 부인방지, 책임추적성, 인증성 | 인증 실패 처리, 데이터 암호화 수준, 침투테스트 통과 기준 |
| 유지보수성 (Maintainability) | 모듈성, 재사용성, 분석성, 수정성, 시험성 | 코드 커버리지 목표, 변경 영향 범위, 정적분석 규칙 준수율 |
| 이식성 (Portability) | 적응성, 설치성, 대체성 | 지원 OS/HW 목록, 설치 소요시간, 마이그레이션 절차 |

(참고) ISO/IEC 25010:2023 개정판에는 상기 8개 외 "안전성(Safety)" 특성이 추가된 것으로 알려져 있습니다 — 안전 관련 NFR은 ISO 26262 요구사항(`references/iso26262-aspice-mapping.md`)과 함께 이 특성으로 분류하는 것을 검토하되, 정확한 판 여부는 표준 원문으로 확인하세요.

## NFR 작성 규칙

1. 각 NFR은 위 표의 **하나의 특성/하위특성**에 명시적으로 매핑합니다(여러 특성에 걸치면 분리해서 별도 NFR로 작성).
2. **정량적 목표치**를 포함합니다 (예: "95번째 백분위 응답시간 ≤ 200ms", "가용률 ≥ 99.9%/월").
3. **실행 가능한 검증 방안**을 반드시 함께 제시합니다.

## 실행 가능/불가능 검증 방안 판별

검증 방안을 제시하기 전에 스스로 다음을 확인하세요: *"이 방법을 실제로 수행할 도구/환경/절차가 존재하는가? 합격/불합격을 객관적으로 판정할 기준이 있는가?"* 둘 중 하나라도 아니오이면 실행 불가능한 방안이므로 다시 작성합니다.

| 특성 | 실행 불가능(금지) 표현 예 | 실행 가능(권장) 표현 예 |
|---|---|---|
| 성능 효율성 | "충분히 빠르게 응답해야 한다" | "부하테스트 도구(예: JMeter/k6)로 동시사용자 500명 조건에서 API 응답시간을 측정하고, 95th percentile이 200ms 이하이면 합격" |
| 신뢰성 | "안정적으로 동작해야 한다" | "72시간 연속 운용 테스트(soak test) 동안 크래시 0회, 메모리 누수 5% 미만이면 합격" |
| 보안성 | "보안을 철저히 한다" | "OWASP ZAP 등 자동화 스캐너로 High/Critical 취약점 0건, 지정된 침투테스트 체크리스트 항목 100% 통과 시 합격" |
| 사용성 | "사용하기 쉬워야 한다" | "지정된 태스크 시나리오 5개를 사전 미숙련 사용자 8명이 수행, 평균 완료시간 ≤ 3분, 태스크 성공률 ≥ 90%이면 합격" |
| 유지보수성 | "유지보수가 용이해야 한다" | "정적분석 도구(예: SonarQube)로 순환복잡도 15 이하, 코드 커버리지 80% 이상 유지 시 합격" |
| 이식성 | "다양한 환경을 지원해야 한다" | "명시된 OS 목록(Windows 11, Ubuntu 22.04) 각각에서 설치 스크립트 실행 후 스모크 테스트 통과 시 합격" |

검증 방법 카테고리(택1 이상, 조합 가능):
- **리뷰/검사(Inspection)**: 문서/코드/설계 검토 — 체크리스트와 판정기준 명시 필요
- **분석(Analysis)**: 정적분석, 수치 계산/시뮬레이션 — 도구/모델과 기준값 명시
- **테스트(Test)**: 동적 실행 기반 검증 — 테스트 환경/부하조건/도구/합격기준 명시
- **데모/시연(Demonstration)**: 정해진 시나리오로 실제 동작 시연 — 시나리오와 관찰 기준 명시

어떤 카테고리든 "도구 또는 절차 + 조건 + 정량적 합격기준"의 3요소가 모두 있어야 실행 가능한 검증 방안으로 인정합니다.
